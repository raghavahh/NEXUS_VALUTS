============================================================
PHASE 10 — FACTUALITY
============================================================

Verify the complete claim chain:

Wikipedia/source
→ extracted facts
→ generated narration
→ claim verification
→ finalized script
→ scene claims
→ visual assignment

UNSUPPORTED claims:
regenerate once
then defer if still unsupported

PARTIALLY_SUPPORTED without sufficient evidence must not silently pass.

Keep the documented limitation that this is an LLM audit, not formal proof.

============================================================
PHASE 11 — QC
============================================================

Verify the ACTUAL media output.

Do not rely solely on manifests or logs.

Required:
- duration validation
- L1 100%
- L2 100%
- L3 100%
- no black frames
- no freeze frames
- scene/source consistency
- final MP4 consistency

Verify that QC actually blocks YouTube upload when it fails.

============================================================
PHASE 12 — PUBLISHING SAFETY
============================================================

Upload must execute only when:

APP_MODE == production
AND skip_upload == False
AND readiness == READY
AND QC == PASS

No CLI bypass.

No:
--upload
--force-publish
or any hidden equivalent.

Publishing:
privacyStatus = private
publishAt = future scheduled time

Verify minimum upload gap and readiness buffer in actual runtime logic.

Verify the final publishAt timestamp is the one actually sent to YouTube.

============================================================
PHASE 13 — IDEMPOTENCY
============================================================

A rerun must not create duplicate YouTube uploads for the same
file_number.

Verify:
file_number → one logical production record → one YouTube video ID

Check retry behavior around:
- API timeout
- OAuth refresh
- upload interruption
- process restart
- rerun after partial completion

The system must recover safely instead of generating duplicate videos.
